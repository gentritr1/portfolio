# Old-draft motion audit

Scope: the 16 existing directions only. New directions, DraftApp, report generation and budget JSON are outside this patch. Implementation follows `ASTRA-MOTION-CRAFT.md`; no upstream component source was copied. The fixed overshoot token is the exact brief value, including its 1.35 control point.

Status: source implementation is complete. Root has verified all 16 keyboard CV confirmations and zero 375 px overflow with forced reduced motion/no-WebGL; sampled 10% interruption and signature checks are recorded in motion-old-drafts-runtime.json. These observations do not establish physical-device frame rate or literal DevTools timeline scrubbing. Subagents have no browser surface in this task. Root's `?review=1&speed=0.1` is equivalent slow playback, not a literal DevTools Animations-panel scrub.

## Common coverage

- Every old entry point mounts `OldDraftMotion` inside its own root. It adds pointer/keyboard pressed state and a short acknowledgement, without changing existing transforms. Each direction owns the requested easing/duration tokens and its feedback palette in its own CSS.
- CV downloads have a visible check and a live confirmation that the download **started**. This does not claim the PDF finished downloading. Existing theme and sound labels remain the authoritative done state. Only Hybrid exposes a theme toggle; Savefile and Primetime expose sound. No unnecessary theme/sound switches were added.
- Native project disclosures retain their content for the exit. Height, opacity, an 8px offset and 4px blur animate for 220ms; interruption samples the displayed height and child styles before cancelling the old animation. Reduced motion uses 10ms and removes the offset/blur.
- `/work/` links preload the destination before navigation. Supported browsers use native shared-image view transitions to the existing `monitor-{slug}` case hero when a visible source image exists. Text-only links use a route crossfade. Unsupported browsers navigate normally after preload. This is a native View Transition implementation, not an assertion that every old draft now has a Motion `layoutId` tile.
- Eight local project surfaces retain old/new snapshots through named View Transitions. The CSS names are direction-specific. Canvas also preloads its reading page and bridges reading/canvas mode changes with a native snapshot transition. Reduced motion commits the new state directly.
- The confidential care file is available in the old local care cases/disclosures and the already-lazy shared CaseStudyPage. It peeks on hover/focus, reverses a spring-controlled 3D lift/flip, exposes 31 architecture decisions, route parity and 16 → 2 API queries, and contains a labelled invented-data recreation. Its palette comes from each draft; reduced motion replaces the face without a flip. The shared case-page import is itself lazy. Facts are connected to the button with an accessible description.
- Existing scene fallbacks, asset provenance and factual content are preserved. Long first-arrival effects were not globally replaced by short button motion. There are no new dependencies.

- `npm run build` passed after care-file integration. A subsequent manifest build passed after the shared case import became lazy. Read-only `node:zlib` graph measurement at that point was entry **20.138 kB** / initial JS **101.849 kB**, below the stored baseline **20.189 / 101.863 kB**. The Vite printed gzip numbers use a different calculation and were not used for this comparison. The final Canvas mode edit was typechecked; root owns the final combined production measurement after its concurrent work. Helpers are imported only from lazy draft/case boundaries; no eager entry, DraftApp, Vite configuration or budget file was edited by this agent.
- Native View Transition fallback is intentionally ordinary navigation/state replacement. Shared images require an actual visible image; text-only rows cannot honestly be described as a tile-to-hero morph. Browser-back shared-element behavior has not been established.
- Minimizing/restoring a desktop window still uses its native hidden state; explicit close gets the retained exit. This remains a narrower implementation than an OS-wide shared-window layout system.
- Root verified all 16 keyboard CV confirmations and zero horizontal overflow at 375 px with forced reduced motion/no WebGL. Eight native disclosure reversals, Desktop and Wall presence, the shared care folder, and selected project/mode changes were sampled at 10% playback. Blueprint native slider release settled to 20%, a 5% step; Canvas camera movement remained bounded. Detailed observations are in motion-old-drafts-runtime.json. Shader skew values, physical touch behavior, every local care surface, live preference changes and every signature state have not each been established by browser observation; their source coverage is listed separately.
- Source follow-ups from the capture pause are complete: Wall measurement ordering and reduced duration, Blueprint predicted release, confidential care folders, the Fast Refresh split, and Canvas reduced-motion completion. No further source edit is pending unless runtime verification finds a defect.
- Care file check for every direction: open its care-platform disclosure or case, focus/hover `.old-care-file`, press to expose the facts, reverse during the flip, then repeat with reduced motion. The shared route is `/work/care-platform`; Hybrid reaches it through the preloaded case link.
- These changes do not establish a Motion `layoutId` morph for every text-only project row, nor do they replace the OS-style minimize/restore state with a shared-layout system. Those limits are explicit so the report cannot be mistaken for every motion-brief checkbox passing.
